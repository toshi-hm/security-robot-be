# Codex Pull Request Review Prompt

## 🎯 目的
Pull Request を Codex (OpenAI) にレビューしてもらう際に使用する標準プロンプトです。すべてのフィードバックを **必ず日本語** で出力させることを重視しています。

## 📋 レビュー時の前提情報
- リポジトリのガイドライン: `CLAUDE.md`
- 進捗と履歴: `report/PROGRESS.md`, `report/summary/DIARY01.md`, `report/DIARY02.md`
- 実装ガイド: `instructions/prompts/00_implementation_guide.md`
- バックエンド実装ガイド: `instructions/prompts/01_backend_implementation_guide.md`

Codex には、上記ドキュメントを参照して文脈を把握した上でレビューするよう促します。

## 🧠 レビュー時のチェック項目
1. コード品質・設計指針に沿っているか
2. 潜在的なバグや欠陥はないか
3. セキュリティ・パフォーマンス面の懸念
4. テストの有無と十分性
5. ドキュメントの整合性と更新漏れ

## 🗒️ 推奨出力フォーマット
1. **概要**: 変更内容の要約 (2〜3行)
2. **重大な懸念点**: ブロッカーとなる問題を箇条書きで提示
3. **改善提案**: 任意の改善アイデア、リファクタリング案
4. **テスト/検証**: テスト状況の評価と不足している場合の提案
5. **参考資料**: 必要に応じて参照した設計書やファイルを明記

すべての文章を自然な日本語で記述し、不要な英語表現は避けます (コードスニペットや識別子を除く)。

## 🧾 ベースプロンプト
以下のテンプレートを Codex アクションやチャットに渡してください。必要な値 (リポジトリ名や PR 番号など) は GitHub Actions や実行環境側で置換します。

```text
REPO: {{REPOSITORY_NAME}}
PR NUMBER: {{PR_NUMBER}}

あなたは熟練したソフトウェアアーキテクト兼コードレビュアーです。以下の要件に厳密に従って Pull Request をレビューしてください。

# 出力に関する必須要件
- すべての説明・指摘・提案は日本語で書くこと。
- コードや識別子は必要に応じて原文のまま引用してよいが、解説は必ず日本語で行うこと。
- レビュー結果は「概要」「重大な懸念点」「改善提案」「テスト/検証」「参考資料」の順序で構成すること。該当しないセクションがある場合は「特になし」と明記すること。

# レビュー手順
1. `CLAUDE.md` を読み、プロジェクトのコーディング規約と作業方針を把握する。
2. `report/PROGRESS.md`、`report/summary/DIARY01.md`、`report/DIARY02.md` で最新の進捗と背景を確認する。
3. 変更ファイルを精査し、設計書 (`instructions/` 配下) の仕様に反していないか確認する。
4. 重大なバグ、セキュリティ問題、設計違反があれば必ず指摘し、修正理由を説明する。
5. テストが不足している場合は、具体的な追加テスト案を提案する。
6. PR 全体に対する最終的な評価 (Approve / Changes Requested) は明記しなくてよい。

# 出力スタイル
- 箇条書きを活用し、読みやすい短い段落でまとめる。
- 具体的なファイル名・行番号を示す際は、GitHub のレビューで参照できる形式を使用する。
- 不明点や追加で確認したい事項がある場合は、質問として明確に列挙する。

以上を遵守し、丁寧で建設的なレビューコメントを生成してください。
```

## 🔄 運用メモ
- PR レビュー ワークフローに組み込む場合は、上記テンプレートを GitHub Actions などからそのまま渡すと Codex が日本語で出力します。
- 追加の社内ルールがある場合は、テンプレート末尾に追記してから Codex に渡してください。
- 指摘内容は常に具体例と根拠を添えてもらうように促すと、より有益なレビューになります。
